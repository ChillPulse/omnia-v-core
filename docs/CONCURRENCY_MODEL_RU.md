# Модель конкурентности OMNIA v2.2 (AT32F403 + ESP32-S3)

Статус: описывает текущую реализацию (ветка `arena/00de572b-omnia-v-core`, fw 2.3.0).
Не заменяет измерения на реальном железе: приоритеты, джиттер и бюджеты циклов не измерены.

## 1. Общая картина

| Узел | Контекст "аудио" | Контекст "команды" | Потоковая модель |
|------|------------------|--------------------|------------------|
| AT32F403 (ядро DSP) | `DMA1_Channel1_IRQHandler` (высший приоритет, половина DMA-буфера I2S) | главный цикл, `omnia_uart_link_poll()` | без RTOS, один main + ISR |
| ESP32-S3 (стример) | собственный UART→I2S тракт | FreeRTOS, закреплённый `uart_rx_task` (core 0, prio 12) | FreeRTOS, мьютексы/семафоры |

## 2. AT32: кто с кем делит DSP-контекст

- **ISR (аудиопоток):** `process_half_buffer()` декодирует u32 I2S-кадры, применяет
  `omnia_dsp_process_block_i32()`, упаковывает обратно для PCM5102A. ISR имеет
  наивысший приоритет (`nvic_irq_enable(..., 0, 0)` — **не измерено** на железе).
- **Главный цикл (команды):** UART-кадры, разобранные парсером из DMA-кольца
  (DMA1_Channel5, циркулярный режим), диспетчеризуются в `dispatch_rx_frame()`.
  Все `omnia_dsp_*()` конфигурационные функции вызываются именно отсюда.
- **Разделяемые данные:** поля `omnia_dsp_ctx_t` (маска блоков, цели громкости,
  коэффициенты биквадов, состояния фильтров, дельта-арена).

### 2.1. Критические секции DSP

Все публичные конфигурационные функции `omnia_dsp_*()` (init, reset_states, set_*,
apply_*, reset_dc_fault, load_aether_factory, read_and_reset_meters) обрамлены
`dsp_enter_critical() / dsp_exit_critical()`:

- на ARM: `cpsid i` … `cpsie i` — маскируются **все** прерывания (грубо, но просто);
- в хост-сборке (тесты): только счётчик глубины, маскирования нет;
- **вложенность:** счётчик `s_dsp_crit_depth`; `cpsie` выполняется только на выходе
  из внешней секции (init → reset_states → recalc_all_coefficients вложены друг в друга).
  Ранняя версия снимала маску на внутреннем `cpsie` — исправлено.

**Правила (для тех, кто трогает код):**
- секция должна быть короткой: внутри ISR та же секция блокирует звук → джиттер;
- изнутри секции нельзя вызывать код, который сам входит в секцию без нужды,
  и нельзя делать I/O (UART, flash, задержки);
- конфигурация громкости/маски не применяется «внутри ISR по порогу»: цели только
  записываются из командного контекста, ISR читает их каждый кадр.

### 2.2. Арена задержек (.sram_ext)

`omnia_dsp_delay_arena_t` (room delay, limiter look-ahead, AETHER delay, Bauer
crossfeed) пишется и читается **только** трактом обработки (ISR). Командный контекст
арену не индексирует; он меняет лишь цели (длительность, коэффициенты) через
критические секции. Ring-индексы 8/9-битные power-of-2 (`& (SIZE-1)`).

### 2.3. Телеметрия и сброс пиков

`omnia_dsp_read_and_reset_meters()` выполняет чтение+обнуление пиков **внутри**
критической секции (иначе пик, записанный ISR между чтением и очисткой, теряется).

### 2.4. UART: кадр и повторы

- байты из DMA-кольца вычитываются в `omnia_uart_link_poll()`; парсер синхронизируется
  по заголовку и проверяет CRC-16/CCITT-FALSE;
- на битый CRC NACK не шлём (seq недостоверен) — потеря ответа обнаруживается хостом
  по тайм-ауту;
- **ACK-дедупликация** в `uart_link.c`: кольцо из 8 слотов по ключу (seq, cmd);
  повторная передача того же запроса не выполняет команду повторно, а досылает
  кэшированный ACK. `GET_SYS_INFO` исключён (идемпотентен и не имеет побочных эффектов);
- доставка не гарантируется транспортно: AT32 не имеет окон/повторов;
  ретраи делает ESP32-мост (3 попытки).

## 3. ESP32-S3: модель стримера

- `at32_bridge.c`: закреплённый на core 0 задача `uart_rx_task` (prio 12) — один
  отправитель/запрос за раз через `g_tx_mutex`; ответы AT32 маршрутизируются по
  `g_reply_sem` + `g_state_lock`; ретраи запросов — на стороне моста;
- задания, не связанные с UART, не делят контекст DSP с AT32: ESP32 лишь
  транспортирует кадры и telemetry в USB/стриминг-часть;
- ESP-IDF проект собирается с глобальным `-flto` в CMake (BOOTLOGO и размер секций
  контролируются скриптом `scripts/check_at32_elf.py` для AT32-стороны).

## 4. Что НЕ сделано (известные ограничения)

- критические секции грубые (полное маскирование IRQ) и не дробятся по подсистемам —
  двойная буферизация атомарных копий конфигурации **не** реализована;
- коэффициенты PEQ/AETHER меняются мгновенно при `*_apply_*()` — перекрёстного
  фейда коэффициентов (20–50 мс) нет; сглаживаются только гейны, задержки, маска/Wet-mix;
- `dc_fault_tripped` сбрасывается **только** сервисной командой `RESET_DC_FAULT`
  (0x1A) с хоста; автоматического сброса нет намеренно;
- корректность приоритетов/джиттера/времени в ISR на реальном устройстве не измерена;
  `g_cpu_load_pct` (счётчик циклов DWT) — инструментация, а не подтверждение бюджета.
