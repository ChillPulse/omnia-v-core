# OMNIA · Пошаговое подключение и прошивка (Windows + VS Code/PlatformIO)

**Стенд, а не изделие.** Рассчитано на конфигурацию, о которой сообщил пользователь (2026-11-27):
ПК с Windows, VS Code + PlatformIO IDE, ESP32-S3-DevKitC-1-совместимая плата (YD-ESP32-S3, N16R8, исправна на Ё-радио), WeAct AT32F403ACGU7 BlackPill (полное соответствие GitHub WeActStudio), фиолетовый GY-PCM5102 (исправен на Ё-радио, фото ожидается), клон ST-Link, USB-UART переходник 3,3 В, мультиметр. Осциллографа/лог.анализатора нет — что это меняет, см. «Ограничения без осциллографа».

Усилитель, K2, динамики, 230 В — **не подключать ни на одном этапе этого документа**. Bluetooth и USB Host выключены и не обсуждаются. Изменение USD/EOPB0 — только после бэкапа и явного решения пользователя (этап 2).

Интерактивная фиксация: [OMNIA_BRINGUP_INTERACTIVE_RU.html](OMNIA_BRINGUP_INTERACTIVE_RU.html) (поля «измерено / прибор / коммит»). Официальные критерии и карточка опыта: [BENCH_VERIFICATION_RECORD_RU.md](BENCH_VERIFICATION_RECORD_RU.md).

## 0. Что подготовить на ПК

1. VS Code с расширением PlatformIO IDE (то же окружение, что и в Ё-радио).
2. Клон репозитория, ветка `main`. В терминале PlatformIO:

```sh
git rev-parse --short HEAD
pio run -e esp32s3_omnia
pio run -e at32f403_dsp
pio device list
```

`pio device list` покажет порты вида `COM3 — USB-SERIAL CH340/CH343` и т.п. Подставлять эти имена в команды ниже. Сборка не прошивает устройство.
3. По желанию (не обязательно для этапов): `bash tests/run_host_tests.sh` — требует WSL или Git Bash + GCC.

## Этап 1 — ESP32 отдельно (ничего больше не подключено)

1. USB-кабель **данных** в порт с CH343P (на YD-ESP32-S3 — правый разъём в той ориентации, как на справочной картинке; сверьте надпись у своей платы). Второй (native USB-C) на этом этапе не трогаем.
2. До включения: мультиметром проверить отсутствие КЗ +5V/GND и +3,3V/GND на гребёнке.
3. Прошивка и монитор:

```sh
pio run -e esp32s3_omnia -t upload
pio device monitor -e esp32s3_omnia
```

Монитор 115200 бод. Ожидается вывод загрузки ESP-ROM → точка входа приложения → инициализация NVS/PSRAM. Отсутствие сообщений об AT32 на этом этапе **нормально**. Консоль UART0 принимает команды заглавными буквами + Enter: `HELP`, `STATUS`, `STOP`. `TONE NOAMP n` осмыслен только на этапе 4 (нужен AT32 + ЦАП). После проверки — закрыть монитор (без него повторная прошивка не зайдёт).

Если лога нет: не тот порт (попробовать второй USB-C — должно появиться второе COM-устройство), кабель «только зарядка», плата не в режиме загрузки (для DevKitC — зажать BOOT при сбросе; на клонах бывает иначе). Сборка/прошивка не трогает NVS и чужие данные.

## Этап 2 — AT32: сначала ТОЛЬКО чтение, ничего не пишем

**Не подключать ничего, кроме ST-Link и питания AT32.**

1. Прозвонить SWD по маркировке WeAct P3: `SWDIO→PA13`, `SWCLK→PA14`, `GND→GND`. `NRST` подключать только если чтение не пошло. Контакт `3.3V` у клона ST-Link может быть **входом Vref**, а может быть **выходом питания** — его назначение до соединения питания установить мультиметром/по документации клона; **источники питания не объединять**.
2. Совместимость ST-Link-клона с AT32 заранее не гарантирована (platformio выбран `stlink`, OpenOCD target at32f403axG — выбор конфигурации, не результат подключения). Первая проверка — только чтение IDCODE/Flash/USD **официальной утилитой Artery** (бесплатно: ICP/ICP Programming от Artery Technology) или OpenOCD в режиме чтения. Записать, чем именно читали, и версию ПО.
3. **До любых изменений**: считать USD/option bytes полностью и сохранить (скриншот + текстовый файл: адреса, значения всех полей). Снять EOPB0 (96 vs 224 КиБ). По возможности сохранить образ всей Flash, если заводская прошивка нужна.
4. Решение по 224 КиБ — **только ваше явное «да»** после бэкапа: изменение EOPB0 по официальной процедуре Artery AN0026 (штатная утилита ICP/ISP, остальные поля сохранить, отключить/включить питание, перечитать и зафиксировать). **Прошивка и CI option bytes никогда не пишут.** Если утилита/клон USD не видит — ничего не стирать, остановиться и сообщить диагностику.
5. После подготовки SRAM:

```sh
pio run -e at32f403_dsp -t upload
```

При рабочем startup на 224 КиБ — мигание PC13 ~каждые 250 мс. При 96 КиБ прошивка по дизайну не стартует DSP/UART (зафиксировано в коде и документации).

## Этап 3 — AT32 автономно (до связи с ESP)

1. Обесточить AT32. Подключить USB-UART 3,3 В: **RX адаптера ← PA9 (TX AT32)**, **TX адаптера → PA10 (RX AT32)**, общий GND. Переходник не обязан питать плату. **Одновременно с ESP эти пины никуда больше не подключать.**
2. ```sh
   python -m pip install pyserial
   python scripts/omnia_bench.py --port COM3
   ```
   Ожидается: `AT32 FW 2.4.0; SRAM 224 KiB; SYSCLK …; SPI id …` и периодический статус с `K2=0`. Это end-to-end проверка связки «verсия в omnia_fw_version.h → SYS_INFO → хост-скрипт» — ожидаемая версия именно 2.4.0.
3. Нет ответа: поменять RX/TX местами, проверить baud 921600, проверить SRAM-режим (этап 2), общий GND, питание. Совместимость утилиты испытана программно, не на вашей плате — расхождения фиксировать в карточку опыта.

## Этап 4 — связь ESP32 ↔ AT32 (ЦАП пока не ставим)

1. Обесточить обе платы. Снять USB-UART с AT32. Соединить: `GND↔GND`, `ESP GPIO7 TX → AT32 PA10 RX`, `ESP GPIO8 RX ← AT32 PA9 TX`, `AT32 PB12 (WS) → ESP GPIO6`, `AT32 PB13 (BCLK) → ESP GPIO4`, `ESP GPIO5 (DOUT) → AT32 PB14`. 5-вольтовые линии не соединять. До подачи питания мультиметром убедиться, что выключенная плата не запитывается через сигнальные линии.
2. Включить; в консоли ESP (UART0, 115200): `STATUS`. Показания свежести/версии должны совпадать с AT32. `K2=0` обязателен.
   Сквозной тональный тест — **только** при отключённых УМЗЧ/K2/динамиках:
   ```sh
   pio device monitor -e esp32s3_omnia   # затем: TONE NOAMP 5  (1 кГц, 5 c)
   ```
   Либо через AT32-переходник (этап 3) + `--tone 5 --no-amp` (см. этап 5). По окончании тест глушит тракт; остаются bypass и −24 дБ.

## Этап 5 — PCM5102A (ТОЛЬКО после фото и сверки)

До подключения — фото платы (см. «Что прислать в письме» ниже) и мультиметр **на выключенной** плате:

- Сопротивление `VIN→GND` (нет КЗ), `XSMT→GND`, `XSMT→3,3V` (должно быть ≫ 0 Ом; если ≈0 — перемычка на XSMT закорочена, решать по фото/прозвонке, `PB0→XSMT` не подключать), `SCK→GND` (на многих GY-PCM5102 коротёж по дизайну — сверить с вашим фото).
- Маркировка регулятора и его входной диапазон: большинство фиолетовых модулей — XC6206P332 3,3 В и 5 В на `VIN`; **не подавать 5 В на голый PCM5102A**. Питание — по маркировке конкретного модуля, не по общим картинкам.

Подключение после подтверждения: `PB12→LCK`, `PB13→BCK`, `PB15→DIN`, общий GND; `SCK→GND` — только если это подтверждает ваша плата; `PB0→XSMT` — только если XSMT не закортён жёстко; без схемы до этого момента не паять. Уровни — 5 В на логические входы запрещены.

Проверка: мультиметр на AC-диапазоне на L/R относительно аналоговой земли — при `TONE NOAMP`/`--tone 5 --no-amp` видно переменное напряжение ~1 кГц (грубая проверка наличия, не точность уровня). Ожидаемые номиналы BCLK ≈ 3,072 МГц / LRCK ≈ 48 кГц **мультиметром не измерить** — нужен осциллограф/лог.анализатор; без него этап G карты проверок считается не закрытым. Выход DAC — линейный уровень.

```sh
python scripts/omnia_bench.py --port COM3 --tone 5 --no-amp
```

Утилита сама запросит MUTE в конце. `K2`/`DC` авария или `K2≠0` — тест откажется стартовать (так и должно быть).

## Ограничения без осциллографа (честно)

- Нельзя закрыть этап G: формат/частота BCLK/LRCK/DATA, XSMT-антивсплеск, реальная 24-битность тракта.
- AC-диапазон мультиметра — только «сигнал есть/нет», не уровень и не искажения.
- «Зелёный» STATUS/ACK не подтверждает физических уровней и выхода ЦАП.
- Значения «измерено» в карточке опыта заполняются только реально измеренными прибором; иначе пункт остаётся НЕ ПРОВЕРЕНО.

## Откат и остановка

Перегрев, запах, нестабильный ток, любые противоречия показаний → отключить питание, ничего не менять наугад, сфотографировать и написать. Проблема с USD/записью AT32 → остановка до бэкапа. Ни один пункт выше не требует разборки клона ST-Link и не меняет чужие прошивки.
