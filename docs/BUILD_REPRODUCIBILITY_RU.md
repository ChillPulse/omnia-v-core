# Версии сборки и контроль AT32 SDK

## Что закреплено

- Платформа Artery PlatformIO: commit `7313140183db3ca5e74e723c2abcc4da82992dc5` в `platformio.ini`.
- Библиотека `ArteryTek/AT32F403A_407_Firmware_Library`: commit `29f8bfd95b190fa38070d2e0fbbb9f3871b0b3f5`, задан в `scripts/at32_sdk_lock.py`. PlatformIO pre-script подготавливает и проверяет её **до** запуска framework builder. Он нужен, потому что builder платформы иначе загружает библиотеку по изменяемому HEAD.
- ESP32 PlatformIO platform: `espressif32@6.10.0`; в проверенной локальной сборке используется ESP-IDF 5.4.0. Отдельный workflow также предусматривает IDF 5.3, что не означает его автоматического выполнения локально.

При отсутствии пакета pre-script загружает точный commit во временный каталог рядом с кэшем и затем устанавливает его; прерванная загрузка не выдаётся за готовый пакет. Повторная сборка проверяет commit и состояние Git. Ожидается чистый checkout; единственное разрешённое неотслеживаемое исключение — созданный `package.json`. Изменённые отслеживаемые, посторонние неотслеживаемые и игнорируемые файлы отклоняются. Это контроль согласованности, **не** защищённая от злоумышленника система подтверждения подлинности.

## Если сборка остановилась на `AT32 SDK lock failed`

1. Прочитать путь и причину из сообщения. Не редактировать SDK внутри общего кэша PlatformIO ради исправления.
2. Сохранить изменения, если они важны. При необходимости **переместить** только указанный каталог пакета в безопасное место вне каталога пакетов PlatformIO; скрипт сам не удаляет существующий каталог и не перезаписывает изменённый или чужой checkout.
3. Повторить сборку: потребуется установленный Git и сетевой доступ к указанному репозиторию/commit. При корректном неизменённом кэше сеть для этой библиотеки не нужна. Удаление кэша может лишить возможности собраться офлайн.
4. Если задан `PLATFORMIO_CORE_DIR`, кэш и сообщение об ошибке относятся к нему, а не обязательно к `~/.platformio`. Для проверок использовать вывод пути и commit в строке `OMNIA AT32 SDK:`.

Не редактировать скрипт и хеш ради обхода проверки, не стирать другие пакеты. Для Windows необходим работающий Git в PATH; код и тесты рассчитаны на работу через стандартные команды Git/Python, но на Windows ещё не проверялись.

## Что пока НЕ гарантировано

Закрепление этих двух Git-коммитов не делает сборку полностью воспроизводимой или побайтово идентичной. Сам PlatformIO Core, пакеты компилятора и загрузчика, другие инструменты и платформенные зависимости ещё не все закреплены или проверены по хешу. Сборщик и ОС могут различаться; также надо сохранить версии, логи, бинарные хеши и исходный commit в журнале испытания. Чистый Git-статус библиотеки не защищает от подмены инструментов. Чтобы получить подтверждение сборки при изменении цепочки инструментов, нужно повторить все тесты, сравнение бинарников и отдельно проверить фактическую работу платы.

Проверки без платы:

```sh
python -m unittest discover -s tests -p test_at32_sdk_lock.py -v
pio run -e at32f403_dsp
python scripts/check_at32_elf.py .pio/build/at32f403_dsp/firmware.elf
python tests/test_at32_elf_check.py .pio/build/at32f403_dsp/firmware.elf
```

Успех сборки и ELF guard не разрешает прошивку устройства и не подтверждает безопасность. Прошивку, option bytes и монтаж выполнять только после подготовки и идентификации конкретных плат.
