# OMNIA: безопасный запуск по этапам

**Версия для стенда, не финальная прошивка устройства.** Bluetooth отложен до фотографии вашего модуля; в этой сборке BT и USB Audio на AT32 по умолчанию выключены. Сборка и CI не подтверждают работу аппаратуры. Усилитель, реле K2, динамики и сеть 230 В к первым этапам **не подключать**.

Актуальные схемы: [ядро стенда](OMNIA_WIRING_STAGE1_CORE.png), [управление усилителем — пока концепция](OMNIA_SCHEMATIC_IC_TRANSISTORS.png). [Описание K1/K2 и ограничений](AMP_CONTROL_SAFETY.md). Старое изображение переделки дисплея — архив, не руководство к пайке.

## Что реализовано и что нет

| Этап | Статус | На что смотреть |
|---|---|---|
| Сборка прошивок, DSP/протокол, AT32 ↔ ESP32 UART/I²S | Код компилируется; аппаратных испытаний не было | Логи, UART, затем сигналы осциллографом/логическим анализатором |
| Тестовый синус AT32 и PCM5102A | Предварительный тест по UART | Проверить на эквиваленте/осциллографе без УМЗЧ |
| USB Audio AT32, ESP32 USB Host, Bluetooth | **Не готовы к подключению как рабочие функции** | USB и BT выключены; Host MSC в приложении не реализован |
| TFT, ИК VS1838B, Web-UI, плеер, радио, сервисное меню | **Ещё не реализованы** | Не ожидайте экрана меню или воспроизведения файлов |
| PB2/PB4, K2 | Команды и экспериментальный секвенсор есть; электросхема и меню не подтверждены | Не подключать реле/УМЗЧ до выбора конкретной платы, измерений и разработки схемы |

## 0. Что нужно

ПК с VS Code + PlatformIO IDE; USB-кабель данных; SWD-программатор CMSIS-DAP/DAPLink либо совместимый ST-Link с поддержкой AT32; отдельный **3,3-вольтовый** USB-UART для самостоятельной диагностики AT32; мультиметр. Для проверки звука желателен осциллограф/логический анализатор. Питание плат — подходящий источник с ограничением тока. Обратитесь к фото/схеме своего клона перед подключением питания: у разъёмов USB и заголовков возможны различия.

Прежде чем подключать провода: питание выключено, проверить отсутствие короткого замыкания +3,3 В/GND и +5 В/GND, подписать контакты. Избегать двух источников, подающих напряжение друг в друга. Программатор обычно должен **видеть** опорное напряжение 3,3 В целевой платы; не считайте Vref надёжным источником питания. Никогда не подавать 5 В на логические TX/RX, SWD или I²S.

## 1. Исходники и тесты на компьютере

Открыть репозиторий в VS Code. В терминале PlatformIO:

```sh
pio run -e at32f403_dsp
pio run -e esp32s3_omnia
```

Внимание: изменения этого этапа пока в рабочей ветке, а не в `main`. После клонирования:

```sh
git switch --track origin/wip/v2.2-direct-safety
```

Без оборудования можно проверить:

```sh
python -m unittest discover -s tests -p test_bench.py -v
gcc -O2 -Wall -Wextra -Werror -Ishared -Isrc/at32/include tests/test_dsp_and_proto.c src/at32/dsp_engine.c src/at32/asrc_farrow.c -lm -o omnia-tests
./omnia-tests
```

В Windows использовать доступный GCC/WSL или результаты Actions. Артефакты `.pio/build/...` создаются локально. Факт успешной сборки не означает, что оборудование готово к эксплуатации.

## 2. Отдельный AT32, программатор и расширение SRAM

1. Ничего, кроме программатора и питания AT32, не подключено. По надписям платы соединить `SWDIO` с `SWDIO` (PA13), `SWCLK` с `SWCLK` (PA14), `GND` с `GND`, `Vref` с 3,3 В цели. `NRST` — при необходимости, если доступен. Сначала проверить питание 3,3 В мультиметром и опознать чип.
2. **До любых изменений** считать и записать в файл настройки USD/option bytes и сохранить существующую прошивку, если она нужна. Потребуется утилита Artery, поддерживающая вашу модель программатора; обычный ST-Link без совместимого ПО может не подойти.
3. Для этой прошивки требуется 224 КБ SRAM. При `EOPB0 = 0xFE` она должна быть включена; для `0xFF` у F403A обычно действует режим 96 КБ. По инструкции производителя и только после сохранения USD изменить настройку штатной утилитой ICP/ISP с сохранением остальных полей, отключить/включить питание и заново проверить настройку. Изменение USD может затронуть защиту/данные: не подтверждать массовое стирание, если его последствия не понятны. **Прошивка не меняет option bytes автоматически.** Если утилита/программатор их не видит — остановиться, ничего не стирать наугад.
4. `pio run -e at32f403_dsp -t upload` для выбранного в `platformio.ini` CMSIS-DAP. Для другого программатора использовать соответствующий протокол и поддержку AT32. Если загрузка не идёт — не менять защиту наугад. Подключение по SWD лучше подтверждать через утилиту производителя.
5. При неподтверждённых 224 КБ прошивка удерживает выходы и мигает PC13 примерно каждые 250 мс; дальнейший DSP/UART не стартует. Это диагностическая индикация, не замена чтения USD. Номинальный HICK/PLL без кварца — ориентировочно 240 МГц; точность частоты пока не подтверждена. При перегреве, нестабильном питании или неожиданном токе выключить стенд.

## 3. Проверка AT32 без ESP32 и без ЦАПа

Подключить UART-переходник **3,3 В**: `RX адаптера ← PA9 (TX AT32)`, `TX адаптера → PA10 (RX AT32)`, GND общий; не соединять эти UART-пины одновременно с ESP32. Переходник не обязан питать плату. Установить pyserial и узнать порт:

```sh
python -m pip install pyserial
python scripts/omnia_bench.py --port COM3
# Linux: python3 scripts/omnia_bench.py --port /dev/ttyUSB0
```

Ожидается ответ `FW`, `SRAM 224 KiB`, номинальная частота, периодический статус `K2=0`, затем завершение. Нет ответа — проверить TX/RX, общий GND, 921600 бод, режим SRAM и питание. Утилита проверена программными тестами, но не испытывалась на вашей плате.

## 4. ESP32 отдельно, затем связь

1. Отключить AT32 и остальные платы. Прошить ESP32 через его USB-UART согласно маркировке вашей платы:

```sh
pio run -e esp32s3_omnia -t upload
pio device monitor -e esp32s3_omnia
```

Монитор — 115200 бод. Проверить загрузку, PSRAM в логах и отсутствие перезагрузок. Если ESP32 сообщает об отсутствии AT32 — на этом этапе ожидаемо. Нет UART-лога: проверьте, к какому из двух USB-портов ESP32 подключён кабель и как на конкретной плате назначен порт консоли. PSRAM должна определиться; указанная в логе выделенная память — не тест качества под нагрузкой. Если NVS не инициализируется, прошивка сообщает об ошибке и не стирает её автоматически: сначала сохранить/проверить данные, а не форматировать наугад.
2. Обесточить оба устройства. Убрать USB-UART с AT32. Соединить **GND ↔ GND**, `ESP GPIO7 TX → AT32 PA10 RX`, `ESP GPIO8 RX ← AT32 PA9 TX`, `AT32 PB12 WS → ESP GPIO6`, `AT32 PB13 BCLK → ESP GPIO4`, `ESP GPIO5 DOUT → AT32 PB14`. Питание каждого узла организовать так, чтобы не было обратного питания; нет соединения 5-вольтовых линий USB. До окончательного включения убедиться мультиметром в отсутствии напряжения на выключенной плате, подаваемого через соединённые сигнальные линии.
3. Включить стенд, проверить лог связи и периодический статус. Отсутствие ошибок сборки/ACK не подтверждает целостность цифрового аудио. При обычном запуске производитель PCM ещё отсутствует, поэтому на входе ожидается цифровая тишина. Дополнительная стендовая консоль ESP32 в UART0 (115200 бод) принимает строки `HELP`, `STATUS`, `TONE NOAMP 5` и `STOP` заглавными буквами. Настроить терминал на отправку Enter как CR или LF. Команда `TONE NOAMP 5` запускает на 5 секунд 1 кГц на ESP32 → I²S → AT32 → ЦАП; допустимо 1–10 секунд. Использовать **только при физически отключённых усилителе, K2 и динамиках**. Телеметрия K2 проверяется, но сама по себе не подтверждает безопасности подключения. Программа старается заглушить ЦАП по истечении времени, при ошибке/потере свежего статуса и по `STOP`; при потере связи MUTE может не дойти — отключить питание. Ожидается подтверждение MUTE, но физический XSMT проверить прибором. При отключённом ЦАПе тест позволяет проверить I²S осциллографом. Команда является экспериментальной и не испытана на реальной плате. По окончании теста выставлены обход DSP и уровень −24 дБ; восстановление профиля вручную пока не реализовано.

## 5. ЦАП PCM5102A: только после сверки конкретной платы

Фиолетовые модули отличаются. Прежде чем подключать 5 В к VIN или менять перемычки, проверьте фото обеих сторон, маркировку регулятора, его реальное подключение и допустимое питание. **Не подавайте 5 В на голый PCM5102A.**

Только после идентификации: `AT32 PB12 → DAC LCK`, `PB13 → BCK`, `PB15 → DIN`, общий GND; `SCK → GND` только если это соответствует данной плате и внутреннему PLL; `PB0 → XSMT` только после проверки, что на модуле перемычка XSMT не закорочена непосредственно на GND или питание. При подтверждённой линии может потребоваться внешняя подтяжка XSMT к GND (например 10 кОм); не применять до проверки штатной обвязки. Формат PCM5102A — I²S, FMT low согласно даташиту; FLT/DEMP — по схеме модуля.

Сначала проверить мультиметром сопротивления XSMT к GND/3,3 В при снятом питании. После включения измерить питание DAC и BCLK/LRCK: при 48 кГц и 32-битных слотах ожидается **около** 48 кГц / 3,072 МГц; HICK даёт погрешность. При отсутствии сигнала отключить питание и искать ошибку. Аналоговые L/R — **линейный уровень**, не выход на динамики и не наушники.

Для тонального теста временно отключить ESP32 UART, подключить переходник как в этапе 3; УМЗЧ/K2/динамики физически отключены:

```sh
python scripts/omnia_bench.py --port COM3 --tone 5 --no-amp
```

На L/R относительно аналоговой земли можно измерить примерно 1 кГц. Уровень в тесте намеренно мал; точная амплитуда зависит от ЦАПа и усиления DSP. В конце утилита запрашивает Mute. При таймауте/прерывании USB питание может оставаться включено — убедиться мультиметром в состоянии PB0 или отключить питание. Никакого испытания с динамиками на этом этапе.

## 6. Позднее

- **Усилитель:** нужны фото обеих сторон конкретной платы, её модель, напряжение и характеристики БП. Только после этого — схема согласования PB4, безопасное включение K2 и измерения. PB8/K1 можно оставить неподключённым.
- **VS1838B:** OUT → ESP GPIO40, питание 3,3 В, общая земля; порядок выводов проверить на вашем экземпляре. RMT-обучение ещё не реализовано — подключение пока не даёт рабочего пульта.
- **TFT:** имеющееся старое изображение переделки противоречиво; не перепаивать, пока не проверены сигналы именно вашей платы и не написан драйвер.
- **USB Audio/USB Host:** необходимо закончить и протестировать. Не подключать внешний VBUS к питанию стримера и не объединять питание USB-портов произвольно. Конфигурацию Type-C, защиту и токи надо проверить на конкретных разъёмах.
- **Bluetooth:** остаётся отключённым до фото и идентификации модуля; ничего не перепрошивать и не припаивать к нему сейчас.
